# 《工业互联网概论》课程项目报告

## 项目名称

PipeGuard——油气管道智能监测与泄漏预警系统

## 摘要

油气管道是能源运输的重要基础设施，具有分布范围广、连续运行时间长和事故影响大的特点。传统人工巡检存在周期长、覆盖不足和异常发现滞后的问题。本项目结合工业互联网的端侧感知、边缘计算、平台服务和数据可视化思想，设计并实现 PipeGuard 原型系统。系统采集压力、进出口流量、可燃气体浓度和振动四类数据，在边缘侧进行标准化和多源融合分析，输出风险分、风险等级及可解释的研判依据，并通过 Web 平台完成实时监测、告警转工单、运维处置和统计分析。测试表明，原型能够区分正常工况和模拟泄漏场景，完整展示工业数据从采集到业务闭环的过程。

**关键词：** 工业互联网；油气管道；边缘计算；泄漏检测；多源数据融合

## 一、研究背景与意义

油气介质通常具有易燃、易爆和污染性。泄漏若未被及时发现，可能造成资源损失、环境污染甚至安全事故。长输管道跨越区域广，单纯依靠人工巡检难以满足实时性要求。

工业互联网通过全面感知、可靠连接、边缘智能和平台化服务，将现场设备数据转化为可操作信息。管道监测是工业互联网的典型应用场景：传感器承担“看见”，网络承担“传递”，边缘与平台承担“理解”，业务应用承担“行动”。因此，本项目既具有工程意义，也能综合展示课程中的关键概念。

## 二、需求分析

### 2.1 功能需求

1. 展示管线长度、介质、位置和运行状态；
2. 实时模拟压力、进出口流量、温度、气体和振动；
3. 根据多传感器数据计算泄漏风险；
4. 展示历史趋势和每项风险贡献；
5. 风险超过阈值时自动生成告警；
6. 支持运维人员确认告警并一键生成工单；
7. 支持课堂中主动注入泄漏数据；
8. 展示设备在线状态、协议、量程和上报延迟；
9. 支持工单状态流转、运营指标分析和告警 CSV 导出。

### 2.2 非功能需求

- 易部署：不依赖外部数据库或第三方包；
- 易理解：算法透明、结果可解释；
- 易扩展：数据、算法、API 和界面分层；
- 易演示：单条命令启动，浏览器即可操作；
- 安全性：限制静态文件访问路径，校验资源标识。

## 三、总体方案

系统采用“端—边—云—用”四层结构。端侧由四类传感器构成；边缘侧完成采集、清洗、时间对齐和风险评分；平台层统一管理管线、遥测和告警；应用层提供可视化与处置入口。

在真实场景中，端到边可使用 Modbus、HART 或 OPC UA，边到云可使用 MQTT。为了保证课堂环境下开箱即用，本原型以 Python 模拟传感器和边缘网关，通过 HTTP 向浏览器提供统一数据。

## 四、关键技术

### 4.1 多源数据融合

单一压力下降也可能由阀门调节或工况变化造成。系统将压力、质量守恒偏差、环境气体和结构振动共同纳入判断。先将各信号映射到 0–1，再按 34%、36%、20% 和 10% 加权。当压力与流量同时异常时增加关联增强，体现“多个独立证据相互印证”的思想。

### 4.2 边缘计算

泄漏预警对时延和连续性敏感。边缘计算可在网络质量不稳定时保持本地分析，只向平台上传特征、结果和必要的原始数据。原型中的模拟器和风险模块对应边缘节点，平均两秒产生一个新采样。

### 4.3 告警与工单闭环

算法发现高风险后创建 `open` 告警。运维人员可将告警一键转换为工单，工单按照“待处理—处理中—已完成”顺序流转，并记录责任人及更新时间。工单完成时关联告警自动变为 `resolved`。相比只弹出消息，这一状态化流程更利于责任追踪、进度检查和事后复盘。

### 4.4 可视化设计

首页按“全局健康—核心指标—管线状态—智能研判—最近事件”的顺序组织；管线详情将最新值、趋势、风险分解和研判依据放在同一视野内。运维工单页集中展示处置进度，分析报告页展示风险分布、告警闭环率、工单完成率与运行评分，减少运维人员寻找信息的成本。

## 五、系统实现

后端采用 Python 标准库：

- `risk.py`：纯函数实现风险融合，易于独立测试；
- `store.py`：线程安全存储、数据模拟、告警和工单状态机；
- `server.py`：多线程 HTTP 服务与 REST 风格 API。

前端使用原生 Web 技术：

- HTML 构建语义结构；
- CSS 实现设计系统、响应式布局和状态颜色；
- JavaScript 完成轮询、趋势绘制、筛选、告警与工单操作；
- Canvas 绘制实时趋势，不依赖图表库。

## 六、测试结果

测试分为算法单元测试和 API 集成测试：

1. 正常工况风险低于 35；
2. 中等压降与流量偏差被识别为警告；
3. 多个严重异常被识别为严重风险；
4. 压力与流量关联增强生效；
5. 健康检查、总览和管线详情返回正确；
6. 无效管线返回 404；
7. 注入泄漏后产生严重风险和新告警；
8. 告警可被确认且状态正确更新；
9. 告警可转换为工单且不能重复创建；
10. 工单只能按规定顺序推进并可自动关闭告警；
11. 统计接口与 CSV 导出格式正确。

系统现有 14 项自动化测试，均通过。

## 七、创新点

1. 不只展示实时数据，还显示每类传感器对风险的贡献；
2. 通过关联增强抑制单一信号误判；
3. 提供可重复的泄漏注入路径，便于教学实验；
4. 完整实现“监测—分析—告警—工单—处置—分析”闭环；
5. 零第三方依赖，降低演示环境不确定性。

## 八、局限与展望

本项目数据为仿真数据，算法阈值基于教学设定，无法替代现场标定。后续可从五方面改进：

1. 接入真实 PLC、RTU 或 MQTT 数据；
2. 引入时序数据库和 GIS；
3. 使用负压波到达时间差估计泄漏位置；
4. 使用真实故障数据训练异常检测模型；
5. 增加巡检、消息推送和应急预案联动。

## 九、结论

PipeGuard 将工业互联网的感知、连接、计算、平台和应用贯穿在一个可运行原型中。项目说明，多源传感与边缘智能能够提升管道状态的可见性和异常响应速度，而平台化管理能够把算法结果转化为可追踪的业务行动。该原型达到了课程项目的设计目标，并为接入真实工业数据保留了扩展空间。
