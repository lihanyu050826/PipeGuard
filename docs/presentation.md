# 课程答辩与演示提纲

建议总时长 8–10 分钟。

## 1. 开场：为什么做（1 分钟）

- 油气管道长距离、连续运行，人工巡检不能实时覆盖；
- 泄漏具有安全、经济和环境三重风险；
- 工业互联网可以把“传感器数据”转化为“可执行告警”。

一句话介绍：**PipeGuard 是一个基于端—边—云架构的油气管道智能监测与泄漏预警原型。**

## 2. 架构与技术（2 分钟）

依次说明：

1. 端侧四类传感器采集压力、流量、气体、振动；
2. 边缘网关负责协议转换、数据清洗和低延迟判断；
3. 平台统一管理管线、设备、遥测和告警；
4. Web 应用服务运行人员。

强调为什么把初步判断放在边缘：低延迟、省带宽、断网可用。

## 3. 算法说明（1.5 分钟）

- 压力下降：泄漏后局部压力通常下降；
- 流量不平衡：入口量大于出口量，违反质量守恒；
- 气体浓度：提供环境侧交叉证据；
- 振动异常：反映喷射或结构扰动；
- 多信号共同异常时提高置信度，避免单点误报。

## 4. 系统演示（3 分钟）

1. 首页展示管线、里程、设备和健康度；
2. 进入“管线监测”，说明实时值和趋势；
3. 点击“注入泄漏演示”；
4. 指出压力下降、流量差增加、风险分升高；
5. 展示每项风险贡献和研判依据；
6. 打开“告警中心”，将新告警一键转为工单；
7. 在“运维工单”中演示“开始处理—完成工单”的状态流转；
8. 打开“分析报告”，说明告警闭环率、工单完成率和 CSV 导出；
9. 打开“设备管理”，说明 MQTT 和边缘节点。

演示前运行：

```bash
python run.py
```

## 5. 总结与展望（1 分钟）

完成了从感知、分析、告警、工单到处置复盘的闭环。当前是教学原型，下一阶段计划接入真实 MQTT、时序数据库、GIS 和负压波定位。

## 常见提问

**为什么不用单一压力阈值？**
工况调整也会造成压力变化，多源融合可降低误报。

**为什么选择边缘计算？**
泄漏预警要求低时延，且现场网络可能不稳定。

**模拟数据是否有意义？**
它用于验证数据链路、算法接口和业务闭环；生产前仍需真实数据标定。

**如何保证工业安全？**
真实部署需网络分区、设备证书、TLS、访问控制、日志审计和安全仪表系统联锁。

**小组最大的创新是什么？**
把多源信号融合做成可解释风险分解，并实现可重复的泄漏注入、工单处置和运营分析闭环。
