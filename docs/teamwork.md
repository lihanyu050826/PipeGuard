# 小组协作建议

可根据实际成员人数合并或拆分角色。

| 角色 | 主要任务 | 对应成果 |
| --- | --- | --- |
| 组长 / 产品 | 需求、进度、成果整合 | README、答辩统筹 |
| 架构与算法 | 端边云方案、风险模型 | `risk.py`、架构文档 |
| 后端与数据 | 模拟器、API、告警 | `store.py`、`server.py` |
| 前端与交互 | 大屏、趋势、交互 | `web/` |
| 测试与文档 | 用例、报告、答辩材料 | `tests/`、`docs/` |

## GitHub 协作流程

1. 每位成员从 `main` 创建功能分支，例如 `feature/risk-model`；
2. 提交信息采用“类型: 内容”，例如 `feat: 增加气体传感器风险特征`；
3. 通过 Pull Request 合并，由至少一名同学复核；
4. 在 Issues 中记录需求、缺陷和答辩准备；
5. 演示前给稳定版本打标签，例如 `v1.0.0`。

建议的提交类型：`feat`、`fix`、`docs`、`test`、`style`、`refactor`。
